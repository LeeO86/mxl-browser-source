# Changelog

## Unreleased (planned 1.3.2)

- **Interaction preview at 25 fps** (SPEC §7.3). While a session controlled the page its preview stayed at `BROWSER_PREVIEW_FPS` (10): the server raises a session to 25 only when it asks with `{"type":"preview","fps":25}`, and the UI never asked (also not in 1.2.0). The UI now asks when its session gets control and asks for the default (`{"type":"preview"}`) when it loses it (toggle off, take-over, timeout, reconnect). The server also drops a session that loses control to at most `BROWSER_PREVIEW_FPS`, so a former controller that does not ask cannot keep 25. `BROWSER_PREVIEW_FPS` stays 10.
  - Tests: unit tests for the reset (toggle off, take-over, timeout, `preview` without `fps`), `tests/unit/web/interact.test.mjs` for the UI client (in CI), and preview rates in `tests/integration/interact_test.py`.

## 1.3.1

- **Service and shared workers and the URL policy** (SPEC §14.3). CEF gives the requests of a service or shared worker no browser, so they reached none of the URL policy's handlers: a page could register a service worker that fetched loopback, the function's own ports, the registry or hosts outside `BROWSER_URL_ALLOW`, and in mode `ograf` anything despite `BROWSER_OGRAF_NETWORK=local` (lab, 1.3.0: all went through, `navigation_blocked_total` did not count them). The 1.3.0 release notes listed this as a known limitation.
  - New setting `BROWSER_SERVICE_WORKERS` (default `false`, restart). Off, renderers remove `navigator.serviceWorker` before the page runs (pages, iframes and cross-origin iframes take their path without one), every request of a service or shared worker is refused and counted as `navigation_blocked_total{reason="service_worker"}` (a shared worker cannot fetch), and a persistent profile loses the registrations made while they were on (`Service Worker/Database` and `ScriptCache`; Cache Storage stays; `service_workers_removed` is logged only when something was removed). YouTube (`youtube.html`, picture and sound) and the OGraf examples work as before.
  - On, the browser has its own request context (sharing the global context's storage) whose `CefRequestContextHandler` applies the same policy to every request of a service or shared worker: `fetch()`, `importScripts()` and the fetches of fetch events, also when the worker starts for a navigation, counted with the usual reasons. A worker that outlived its page after a navigation to another site reached no handler (lab); a main-frame navigation that leaves an origin now stops all service workers (DevTools `ServiceWorker.stopAllWorkers`). The worker's own same-origin script still reaches no handler: use `true` only with a NetworkPolicy egress fence.
  - Tests: unit tests for the setting, `checkServiceWorker`, `sameOrigin` and the profile cleanup; `templates/service-worker.html` and `tests/integration/sw_test.py` in CI (the default container; a second one off, with a cross-origin iframe and a shared worker, and on).

- Soak (lab, `docs/performance.md`): 2 h, 8 layers, 52 172 actions without a failure; GPU memory and JS heap flat; 2 missed grains (host load, no OGraf cause found), 4.9 % late paints that grow with the number of layers animating at once (a held frame, never a broken one; fixed by the frame pipeline above), and the CEF RSS still rising by about 25 MiB/h at the end.
- Frame loop (M5, `docs/performance.md`):
  - **Frame pipeline** (`BROWSER_FRAME_PIPELINE`, default `1`): up to two converted frames wait and the tick commits the oldest, so a paint that misses its tick (Chromium paints a busy page at its display deadline, 17–20 ms after the BeginFrame, ready 23–28 ms after it) is shown at the next tick instead of being replaced. Lab, 1080p50, 150 s runs, held frames with 2/4/8 animated elements: page 1.45/0.95/1.00 % → 0.10/0/0.07 %, OGraf 1.64/0.91/0.99 % → 0/0/0 %, EBU examples 1.04/1.01/33.6 % → 0/0.07/0 %. Cost: one period more latency while a frame waits (most of the time), counted by `BROWSER_VIDEO_DELAY_GRAINS=auto`. `0` restores the 1.2.0 behaviour. The remaining 0.07–0.13 % in 10-minute runs are BeginFrames Chromium answers with no paint at all.
  - The converter and its pool run `SCHED_FIFO` 9, below the tick's 10 (`BROWSER_REALTIME`, default `true`); `BROWSER_CONVERT_THREADS` (default 4) is now a setting. Real-time priority needs `RLIMIT_RTPRIO` ≥ 10 for the uid-1000 process: `--ulimit rtprio=10` (Compose `ulimits.rtprio`, set in the demo); `--cap-add SYS_NICE` alone does not give it. With it, 0 missed grains in 352 567 measured grains.
  - **WebGPU off** (`BROWSER_WEBGPU`, default `false`): `disable-features=WebGPUService,WebGPUBlobCache`, so `navigator.gpu.requestAdapter()` answers `null` without starting Dawn on the image's missing Vulkan driver (a helper crashed with "stack smashing detected" after such a probe in the M4 soak). It does not stop every probe: the 8 h soak still had one "stack smashing detected" in a short-lived helper, at the first load of a WebGPU-probing graphic (no grain missed, none in the 8 h after it). Known, not fixed.
  - `BROWSER_CHROMIUM_FLAGS_APPEND`: `--disable-features`, `--enable-features`, `--disable-blink-features` and `--enable-blink-features` are merged with the function's own lists instead of replacing them (Chromium reads only the last), and the comma-split rest of such a list continues it.
  - Diagnosis (with `BROWSER_DEVTOOLS=true`): `GET /api/v1/debug/frame-trace` (every BeginFrame, paint, conversion and commit of the last ~40 s with TAI times; `tests/tools/frame_trace.py`) and the histograms `begin_frame_dispatch_seconds`, `paint_copy_seconds`, `convert_wait_seconds`, `frame_ready_seconds`; finer buckets around the period. `paint_latency_seconds` now measures from the BeginFrame the paint belongs to (the newest dispatched before it), not the newest posted.
  - OGraf: clearing a layer replaces its iframe instead of navigating it to `about:blank`. Measured: it frees only about 7 MiB; the ≈ 270 MiB that stay after clearing all layers are a high-water level of the GPU process and renderer reached within 15 minutes (the same after 2 h), not a per-layer leak (`docs/performance.md`).
  - Tests: `templates/frameloop/` (GSAP 3.12.5 vendored, notice in `THIRD_PARTY_NOTICES.md`), the lab graphic `tests/integration/ograf/anim`, `tests/integration/frameloop_bench.py`, unit tests for the pipeline, the paint stamps and the new settings.
- Frame clock and audio (M6, `docs/performance.md`):
  - **Internal frame clock** (`BROWSER_FRAME_CLOCK`, **default `internal`**; `external` keeps 1.2.0's behaviour): `internal` lets Chromium pace the page with its own BeginFrame source at the house rate, as OBS, CasparCG and gstcefsrc do, instead of one `SendExternalBeginFrame` per grain, whose CEF 144 arguments are wrong (frame time = the call time, a null deadline, a fixed 60 Hz interval, and a BeginFrame dropped while one is pending; CEF #4311). The phase is locked to TAI: CEF sets the vsync timebase in `SetWindowlessFrameRate`, so the UI thread calls it at T(k+1) + φ (`BROWSER_FRAME_CLOCK_PHASE_MS`, default 0) and anchors again after a load, a new browser or a phase error over 1 ms. The frame pipeline stays. 1080p59.94 and 29.97 keep external BeginFrames (`frame_clock_fallback`). New metrics `frame_clock{mode}`, `frame_clock_phase_error_seconds`, `frame_clock_locks_total{reason}`, `frame_clock_late_anchors_total`; the frame trace has `anchor` events and `frame_clock`/`phase_ns`.
  - **Audio timeline:** an upstream loss (the packets' capture times jump because Chromium's loopback skipped ahead) is filled with exactly the lost length of silence, so the FIFO keeps its fill (`audio_gaps_total`, `audio_gap_seconds_total`). An underrun no longer re-primes to the 60 ms target: output resumes with one grain plus a packet, late audio that its silence stood in for is dropped down to the target (`audio_underrun_seconds_total`, `audio_realigned_seconds_total`), and the controller may correct ±2000 ppm while the fill is more than 20 ms off. A stream starts at the target without cutting its first milliseconds, is played out when CEF stops it (2 s after the page went quiet), and an `OnAudioStreamError` no longer silences the flow (`audio_stream_events_total{event}`). `audio_resets_total` now counts only overruns.
  - `GetAudioParameters` asks for the layout of `BROWSER_AUDIO_CHANNELS` (SPEC §6): 7.1 for 8 (and 16, channels 9–16 silent), stereo otherwise.
  - Tests: `grain_reader audio` (gaps and tone phase jumps on the MXL output) and `counter --out`, `tests/media/make_clips.sh` (VP9/Opus clips at 25, 50, 29.97 and 59.94 fps with the frame number as bar code and a 1 kHz tone), `templates/video.html`, `tone.html` with level and on/off switching, `tests/integration/cadence_bench.py`, `frame_trace.py` for the internal clock, unit tests for the frame clock, the gap detector, the underrun recovery and stream start and stop.
- Audio stalls (M7, `docs/performance.md`):
  - **Cause found and fixed.** The YouTube underruns of M6 (12–13 per 2 min) were Chromium's capture thread in the browser process (`AudioInputDevice`, which calls `OnAudioStreamPacket`) blocked for 80–480 ms in the ext4 journal: it writes histograms into Chromium's persistent histogram file (`BrowserMetrics/*.pma`, a shared file mapping in the CEF cache under `/tmp`, on the host's disk), and the first write to a page that writeback had cleaned waited for the journal commit whenever other processes wrote to the disk. The audio came late, not lost (continuous `pts`, no gap fill). The stalls came and went over the day; CPU pinning and CPU load had no effect. `<cache>/BrowserMetrics` is now a link into `/dev/shm` (`browser_metrics_on_tmpfs`); `--disable-features=PersistentHistograms` does not move the file in CEF 144.
  - **Adaptive audio target** (`BROWSER_AUDIO_BUFFER_MAX_MS`, default 300) as a safety net for late bursts that remain: an underrun raises the 60 ms target by the silence it played (up to the maximum), so the late audio is kept and the next stall of that size is absorbed; after 10 s without an underrun the target falls back at 1 ms/s (1000 ppm, feed-forward to the controller). The video delay follows in whole grains, one grain per tick (a repeat while the audio plays the silence, a skip per period of decay), so lip sync holds (A/V offset 21–28 ms at targets of 60–300 ms, as at a fixed 60 ms). The ring and the pool hold the extra grains (1080p50 v210a: 12 sets, about 100 MB more memory). At or below `BROWSER_AUDIO_BUFFER_MS` the target is fixed. Replaying a bad period's stall pattern: 7 underruns (1.1 s) per 150 s with a fixed 60 ms target, 2 (0.2–0.3 s) with the adaptive one. New metrics `audio_target_seconds`, `audio_target_raises_total`, `video_delay_grains`; `/api/v1/status` `audio.target_ms`, `audio.video_delay_grains`.
  - Diagnosis (with `BROWSER_DEVTOOLS=true`, like all `/api/v1/debug/` routes): `GET /api/v1/debug/audio-trace` (every packet's arrival, `pts` and the FIFO, every grain's fill and target, about 100 s), `POST /api/v1/debug/audio-hold?ms=` (with `BROWSER_DEVTOOLS=true`: hold the page's audio and deliver it at once, a late burst on demand), `tests/tools/audio_trace.py`, `tests/tools/audio_threads.py` (the audio threads' states from `/proc` during a stall); `cadence_bench.py` records the audio trace, the media position and the other load on the container's CPUs.
- Fixes from the release review (before 1.3.0):
  - With `BROWSER_ON_PAGE_ERROR=transparent` or `black`, a ready page sent the substitute on every tick without a new paint (a static page, a held lower third, a late paint): it holds its last frame again.
  - An OGraf upload is checked for the token before its body is stored; at most 2 uploads at once (429), each within 10 minutes (408).
  - An upload or delete no longer deletes a package that a layer loaded meanwhile; a restore whose graphic is gone shows the layer in `error`.
  - A second load on a layer rejects the first at once instead of leaving it to the 10 s timeout.
  - Internal frame clock: anchors skipped before the browser exists are not counted as late; a drift relock needs the error on 3 grains in a row (a preemption read as drift). The phase error is modelled, not measured.
  - Adaptive audio target: the video delay counts nominal grains (it jittered at 59.94 and 29.97); the target goes back to the base 10 s after the last underrun while no stream plays; when the late audio turns out to be lost the target falls to the fill at once (`audio_target_lowered_total`); the video delay shrinks by at most one grain per 25 ticks, so a target that falls in one step gives single skipped frames half a second apart instead of a run (after lost audio, lip sync converges at that pace); the FIFO holds three times the largest target (overflow counted: `audio_fifo_overflows_total`); the frame and audio traces are lock-free and need `BROWSER_DEVTOOLS=true`.
  - Chromium's histogram directory is `/dev/shm/mxl-browser-source-metrics-<NMOS_SEED>-<uid>` (one per instance), and a failed link is logged as such.
- Upgrade from 1.2.0:
  - Add `--ulimit rtprio=10` (Compose `ulimits: {rtprio: 10}`, now in the demo and host files) for real-time priority of the tick and converter threads; without it they run at normal priority and log `tick_priority_normal`.
  - **The internal frame clock is the default** (`BROWSER_FRAME_CLOCK=internal`); `BROWSER_FRAME_CLOCK=external` restores 1.2.0's external BeginFrames. In internal mode the function sends no BeginFrames, so `begin_frames_total` stays 0; watch `frame_clock_locks_total` and `frame_clock_phase_error_seconds` instead.
  - **The video leaves one period later** (frame pipeline, `BROWSER_FRAME_PIPELINE=1`). `BROWSER_VIDEO_DELAY_GRAINS=auto` counts it; a fixed `BROWSER_VIDEO_DELAY_GRAINS` now has one period of A/V shift (the video late): reduce it by 1, or set `BROWSER_FRAME_PIPELINE=0`.
  - `mode` defaults to `page`, so an existing `config.json`, preset or export shows its page as before.
  - The OGraf library lives on the `/config` volume (`BROWSER_OGRAF_DIR`, `<state>/ograf`) and grows with every uploaded ZIP (up to `BROWSER_OGRAF_UPLOAD_MAX_MB` each, unpacked up to 4×; a replaced version is deleted once no layer uses it). Size the volume for it.
  - Chromium's histogram file moves to `/dev/shm` (one 4 MiB `.pma` per instance, measured) unless the cache is on a tmpfs already; `--shm-size 1g` as before covers it.
  - Memory: the adaptive audio target (`BROWSER_AUDIO_BUFFER_MAX_MS=300`) sizes the delay ring and the buffer pool for up to 240 ms of extra video delay, allocated at start. Extra memory per format: 1080p50 about 100 MB (`v210a`, 12 sets of 8.3 MB; `fill_key` 133 MB, `v210` 66 MB), 1080p59.94 about 125 MB (15 sets; `fill_key` 166 MB), 2160p50 about 400 MB (12 sets of 33 MB; `fill_key` 530 MB), 2160p59.94 about 500 MB (15 sets; `fill_key` 664 MB). `BROWSER_AUDIO_BUFFER_MAX_MS=60` (the base) turns it off and saves that memory. The audio FIFO grows to at most 149 k frames per channel (about 1.2 MB in stereo).
  - The `/api/v1/debug/` routes answer 404 unless `BROWSER_DEVTOOLS=true`.
  - Ports are unchanged.

## 1.1.0

- Interaction window: back, forward and reload buttons next to the Interact toggle (`POST /api/v1/source/back` and `/forward`; `can_go_back` and `can_go_forward` in the page state, from CEF's `OnLoadingStateChange`).
- Text can be selected with the mouse. Moves while a button was down did not carry the button flag (`EVENTFLAG_LEFT_MOUSE_BUTTON`), and Chromium ends a drag at the first such move. The server now keeps the buttons that are down and puts them on every down, move and up; a click focuses the page first; a leave or the end of control releases a button still down. Double and triple click select a word and a line.
- WebAuthn is hidden from pages by default (`BROWSER_WEBAUTHN=false`, new): windowless CEF cannot show Chromium's passkey or QR code dialog, so a sign-in page that offered a passkey (Microsoft Entra ID behind Zscaler) hung. Without `PublicKeyCredential` sign-in pages offer push, a code or a password (Entra's sign-in options no longer list the passkey).

## 1.0.0 - 2026-10-06

First release: SPECIFICATION is `SPEC.md`, lab results and decisions are in `IMPLEMENTATION_PLAN.md`.

- A web page rendered offscreen with CEF 144 (GPU through ANGLE on NVIDIA, or software), one external BeginFrame per MXL grain index: video as v210, optionally with a key (`v210a` or a separate key flow), and float32 audio at 48 kHz, A/V-aligned (automatic video delay).
- NMOS node (IS-04, IS-05 v1.2, BCP-007-03) with nmos-cpp: senders report their real domain and flow in `/active`, `master_enable` stops a flow and survives a restart; static registry by default, DNS-SD (`local.`) on request.
- Web UI and API: preview, interaction with the page (mouse, keys, text, IME, wheel), CasparCG-style templates, DevTools through `/devtools/` (off by default), config export and import.
- Robustness: renderer crash and page hang recovery with backoff, dialogs, popups, downloads and permission requests never block, busy ports refused before anything is created, the own MXL domain on a tmpfs (root or domain directory).
- Metrics with the `mxl_browser_source_` prefix, process and CEF CPU/memory, Grafana dashboard; Compose demo, host and GPU files; Kubernetes examples; single-node RKE2 notes.
- Image about 900 MB, uid 1000; CI runs unit tests, the integration tests of SPEC §17 in software mode (including the start → SIGTERM lifecycle) and the AMWA suites.

Known limitation: the output is not yet free of single repeated frames. SPEC acceptance criterion 2 asks for 0 repeated grains in 1 h at 1080p50; 1 h soaks on the lab host (A16, GPU mode, `counter.html`) had 0 missed grains, but 11 repeat/skip pairs in 180 001 grains on a quiet host and 273 repeats with 35 skips in 180 002 grains while other lab work ran (0.15 %). Each is a paint that reaches the tick a little late. Released with the owner's agreement; the fix follows in 1.0.x.
